# P0-3 / P0-4 / P0-5 修复实现计划（数据库写错误冒泡 · 显式批量语义 · 蒙版坐标换算）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 SQLite 写失败不再被静默吞掉（含 GUI 侧锁等待）、把「多行即批量」改成显式开关、修掉蒙版涂抹与图像的坐标偏移。

**Architecture:** 后端把三处 `let _ = conn.execute(...)` 收敛成返回 `AppResult` 的小函数（`storage::init` / `migrate_legacy_columns` / `insert_image` / `finish_task_row` / `reclaim_orphan_tasks` / `encrypt_plaintext_keys`），worker 侧把库错误顺着已有的 `task-progress` 事件推给前端，不新增事件名、不改前端。前端把提交语义与指针几何抽成两个纯函数模块（`src/lib/submission.ts`、`src/lib/mask-geometry.ts`），用 Node 原生 `node --test` 跑测试（不引新依赖），组件只做接线。

**Tech Stack:** Rust 2021 + rusqlite 0.37（bundled SQLite）+ Tauri 2；React 19 + TypeScript 5.8（`strict`）+ Vite 6；测试用 `cargo test` 与 `node --test`（Node ≥ 22.18 自带 TS 类型擦除）。

**Spec:** `docs/DESIGN.md`（§5 功能清单第 8/10 项、§10 MCP 无头模式第 168 行「写库三条硬约束」、§11 关键决策记录）。本计划对应 2026-10-31 项目体检里的 P0-3 / P0-4 / P0-5 三条，体检结论未落成独立文档，三条问题描述见本文件开头「Global Constraints」下方「问题清单」。

## Global Constraints

- 不新增 Rust crate 依赖，不新增 npm 依赖（`package.json` 的 `dependencies` / `devDependencies` 保持不变）。
- 后端错误一律走既有 `AppError` / `AppResult`（`src-tauri/src/error.rs`），不引入新错误类型；`AppError::Db` 已经是**不可重试**（`is_retryable()` 返回 false），不要改这条语义。
- 库写失败**不得**用 `let _ =` 吞掉。唯一允许的忽略：旧库补列时 SQLite 报 `duplicate column name`（正常路径）。
- GUI 启动阶段（`setup`）仍然**不允许**因为库写失败而 panic 退出：从 Finder 启动时 panic 只表现为「双击没反应」，比现状更糟。库坏了要让后续每一次写都报错，而不是在启动时静默或启动时崩掉。
- 前端提交语义必须显式：换行不再自动等于批量任务；`数量` 只在单条模式生效。批量开关进会话草稿（`draft_json`）。
- 蒙版涂抹坐标必须与 `object-contain` 实际渲染出来的图像内容区对齐，不得偏移。
- 注释与 UI 文案沿用现有中文风格，一条注释说清「为什么」，不复述代码。
- 验证命令（在本仓库根目录）：Rust 侧 `cd src-tauri && cargo test`；前端侧 `npm test` 与 `npm run build`。每个任务结尾必须跑到全绿。

```rust
/// 旧库补列。列已存在（duplicate column）是正常路径，跳过；
/// 其他错误（表不存在 / 库损坏 / busy）必须冒出来——否则老库静默缺列，
/// 要等到第一次 INSERT 才炸，那时已经看不出是迁移失败。
fn migrate_legacy_columns(conn: &Connection) -> AppResult<()> {
    add_column_if_absent(
        conn,
        "providers",
        "api_key",
        "ALTER TABLE providers ADD COLUMN api_key TEXT NOT NULL DEFAULT ''",
    )?;
    add_column_if_absent(
        conn,
        "tasks",
        "total",
        "ALTER TABLE tasks ADD COLUMN total INTEGER NOT NULL DEFAULT 1",
    )
}

/// `table` / `column` / `ddl` 全部来自本模块写死的 `&'static str`，不接受任何外部输入，
/// 因此 `format!` 拼 PRAGMA 不存在注入面。
fn add_column_if_absent(
    conn: &Connection,
    table: &'static str,
    column: &'static str,
    ddl: &'static str,
) -> AppResult<()> {
    if column_exists(conn, table, column)? {
        return Ok(());
    }
    match conn.execute_batch(ddl) {
        Ok(()) => Ok(()),
        // GUI 与 MCP 同时首次启动时可能双双跑到这里，后到的一方报 duplicate
        Err(e) if is_duplicate_column(&e) => Ok(()),
        Err(e) => Err(e.into()),
    }
}

fn column_exists(conn: &Connection, table: &str, column: &str) -> AppResult<bool> {
    let mut stmt = conn.prepare(&format!("PRAGMA table_info({table})"))?;
    let names: Vec<String> = stmt
        .query_map([], |r| r.get::<_, String>(1))?
        .filter_map(|r| r.ok())
        .collect();
    Ok(names.iter().any(|n| n == column))
}

fn is_duplicate_column(e: &rusqlite::Error) -> bool {
    matches!(e, rusqlite::Error::SqliteFailure(_, Some(msg)) if msg.contains("duplicate column name"))
}
```

```rust
/// 进程重启 = 所有 in-process worker 已死，库里残留的 `status='running'`
/// 不可能再有人推进，必须批量收尾，否则 UI 永远卡在「生成中」无法清理。

pub fn reclaim_orphan_tasks(conn: &rusqlite::Connection) -> AppResult<u32> {
    let n = conn.execute(
        "UPDATE tasks SET \
           status = CASE WHEN (SELECT COUNT(*) FROM images i WHERE i.task_id = tasks.id) > 0 \
                         THEN 'completed_with_errors' ELSE 'canceled' END, \
           error = COALESCE(NULLIF(error,''), \
                     CASE WHEN (SELECT COUNT(*) FROM images i WHERE i.task_id = tasks.id) > 0 \
                          THEN '进程重启，任务中断（已产出的图片已保留）' \
                          ELSE '进程重启，遗留任务已自动取消' END), \
           finished_at = COALESCE(finished_at, ?1) \
         WHERE status='running'",
        params![chrono::Utc::now().to_rfc3339()],
    )?;
    Ok(n as u32)
```

```rust
/// 一次性把存量明文 API Key 加密回写（已带 `enc:v1:` 前缀的跳过）。
/// 幂等，所以每次启动跑一遍；失败必须冒出去——静默跳过等于"加密存储"只对
/// 之后新存的 key 生效，老数据一直裸奔而没人知道。
pub fn encrypt_plaintext_keys(conn: &Connection) -> AppResult<usize> {
    let mut plain: Vec<(String, String)> = Vec::new();
    {
        let mut stmt = conn.prepare("SELECT id, api_key FROM providers WHERE api_key <> ''")?;
        let rows = stmt.query_map([], |r| Ok((r.get::<_, String>(0)?, r.get::<_, String>(1)?)))?;
        for row in rows {
            plain.push(row?);
        }
    }
    let mut updated = 0;
    for (id, key) in plain {
        if key.starts_with(crate::crypto::PREFIX) {
            continue;
        }
        let enc = crate::crypto::encrypt(&key)?;
        conn.execute(
            "UPDATE providers SET api_key = ?2 WHERE id = ?1",
            params![id, enc],
        )?;
        updated += 1;
    }
    Ok(updated)
}
```

```ts
/**
 * 工作台提交语义。抽成纯函数是因为这三条规则过去全靠组件里的
 * `split("\n").length > 1` 隐式判断，改一行文案就会悄悄改变"提交几个任务"。
 */

export interface Submission {
  prompt: string;
  n: number;
}

/**
 * `batchMode` 必须由用户显式打开：一段跨行的完整提示词（长描述、模板追加）
 * 过去会被拆成 N 个互不相关的任务，并把用户选的「数量」静默改成 1。
 * 批量模式下每行 1 张是协议限制之外的产品选择（每行内容不同，n 张同 prompt 没意义）。
 */
export function buildSubmissions(text: string, batchMode: boolean, count: number): Submission[] {
  const trimmed = text.trim();
  if (!trimmed) return [];
  if (!batchMode) return [{ prompt: trimmed, n: count }];
  return trimmed
    .split("\n")
    .map((s) => s.trim())
    .filter(Boolean)
    .map((prompt) => ({ prompt, n: 1 }));
}

/** 提交中途失败后，输入框里该剩下的文本（失败那行及其后续，改完可接着发）。 */
export function remainingText(submissions: Submission[], submitted: number): string {
  return submissions.slice(submitted).map((s) => s.prompt).join("\n");
}

/** `next === undefined` 表示这次回填没涉及提示词，保持现状；`""` 是显式清空。 */
export function pickPrefillPrompt(current: string, next?: string): string {
  return next === undefined ? current : next;
```

```ts
/**
 * 蒙版编辑器的坐标换算。
 *
 * 画布 CSS 是 `w-full max-h-[420px] object-contain`：元素盒（getBoundingClientRect）
 * 与真实图像内容并不总是一样大——被 max-height 夹住时图像居中、两侧留白。
 * 指针坐标必须先减掉这段留白再换算到画布内部分辨率，否则涂出来的蒙版整体偏移，
 * 竖图尤其明显（1024x1536 会横偏 115px）。
 */

export interface Point {
  x: number;
  y: number;
}

export interface Size {
  width: number;
  height: number;
}

export interface Box extends Point, Size {}

/** object-contain 后图像内容在元素盒里的实际矩形。 */
export function contentRect(canvas: Size, box: Size): Box {
  const scale = Math.min(box.width / canvas.width, box.height / canvas.height);
  const width = canvas.width * scale;
  const height = canvas.height * scale;
  return { x: (box.width - width) / 2, y: (box.height - height) / 2, width, height };
}

/**
 * 指针（已减去元素盒左上角）→ 画布像素坐标。
 * 落在留白里时夹到画布边缘：涂抹笔触可以超出图像显示范围，但画布坐标不能为负，
 * 否则 destination-out 会作用在画布外、导出的蒙版与底图错位。
 */
export function toCanvasPoint(pointer: Point, canvas: Size, box: Size): Point {
  const c = contentRect(canvas, box);
  const x = ((pointer.x - c.x) / c.width) * canvas.width;
  const y = ((pointer.y - c.y) / c.height) * canvas.height;
  return {
    x: Math.min(Math.max(x, 0), canvas.width),
    y: Math.min(Math.max(y, 0), canvas.height),
  };
}
```
